# 4.3倍ブル

開発者個人が「楽天日本株4.3倍ブル」の基準価額、保有状況・評価損益、投資・回収の月次集計を確認するシンプルなPWAです。ログイン不要。GitHub PagesとGitHub Actionsで動作し、常時起動するサーバーやAPIキーは不要です。

## 表示内容

- 最新公表日の基準価額（1万口あたり）と前日比（円・小数点以下2桁の％）。
- 初期保有の口数と平均取得単価（円 / 1万口）を手入力し、それ以降の投資・回収を約定日と1,000円単位の金額で記録します。
- 最新の公表済み基準価額を使い、保有口数・平均取得単価・保有分の取得金額・評価額・評価損益（円・％）と評価基準日を表示します。口数は手動補正できます。
- 保有分の評価損益を0％にするために必要な日経平均の1日分の騰落率を、4.3倍換算の概算として表示します。
- 日本時間の毎月1日から本日までの投資額・回収額・損益を表示し、翌月1日に集計を切り替えます。保有口数・取得単価・全履歴は引き継ぎます。
- 月〜日を1週間として、その直前の金曜日から本日までの公表済みデータ。新しい日付順。
- 金曜日に値がなければ、それ以前の直近公表日を起点に表示。前日比は一覧の起点も含め、直前の公表日との比較。
- 週の切り替えと「本日」の判定は日本時間。土日祝など値がない日は補完しません。
- 当日分がなければ「本日分の公表データなし」と最新公表日を表示します。起動中の日付変更とアプリへの復帰にも対応しています。

出典は[楽天投信投資顧問の公式CSV](https://www.rakuten-toushin.co.jp/assets/csv/chart_100019.csv)です。「基準価額(円)」列を使用します。[公式ファンドページ](https://www.rakuten-toushin.co.jp/fund/nav/ribla43/)と[楽天証券の詳細](https://www.rakuten-sec.co.jp/web/fund/detail/?ID=JP90C000CCD0)も参照できます。販売会社と運用会社で掲載時刻が異なる場合があります。

## 保有情報と損益

1. 「初期保有を設定・変更」で、記録開始日（任意）・初期口数・平均取得単価を設定します。平均取得単価は小数にも対応し、保有なしの場合は口数・単価ともに0を入力できます。初期取得額は開始日の属する月の投資額に含めます。既存バージョンの保存済み保有情報も初期保有として引き継ぎ、開始日未設定の初期保有は月初への繰越として扱います。
2. 「投資・回収を記録」で **約定日（基準価額が決まる日）** を選びます。金額の初期値は1,000円で、**1,000円を投資**／**1,000円を回収** の1クリックごとに記録します。金額は±1,000円ボタンか直接入力で変更できます。約定日は本日以前、開始日を設定した場合はその日以降に限ります。
3. 口数のずれは「保有口数のずれを補正」で、補正日と証券会社に表示される実際の口数を入力して直します。投資額・回収額と保有分の取得金額を維持して口数・平均取得単価を補正します（0口への補正では保有分の取得金額も0）。日付順、同じ日付では記録順に計算するため、補正後に同日の売買を追加すると補正済みの口数から計算します。
4. 履歴の **取消** で誤った記録を外し、日付や金額を直して登録し直せます。直後なら **取消を戻す** で復元できます。初期保有を変更しても投資・回収・補正の履歴は残ります。

入力値と履歴はこのサイト・このブラウザのlocalStorageに保存し、サーバーやGitHubには送信しません。別の端末・ブラウザとは同期せず、サイトデータを削除すると失われます。

- 初期取得額 = 初期口数 ÷ 10,000 × 初期平均取得単価
- 今月の投資額 = 今月に開始した初期取得額 ＋ 当月の追加投資額の合計
- 今月の回収額 = 当月の回収額の合計
- 月初繰越評価額 = 前月末時点の保有口数 ÷ 10,000 × 前月末までの直近の公表済み基準価額（今月開始の場合は0円）
- 売買口数（概算）= 記録金額 ÷ 約定日の基準価額 × 10,000（1口単位に四捨五入）
- 保有分の取得金額は追加投資分を加え、回収時は売却口数に対応する取得金額を差し引きます。
- 評価額 = 保有口数 ÷ 10,000 × 最新の公表済み基準価額
- 保有分の評価損益 = 評価額 − 保有分の取得金額
- 損益率 = 保有分の評価損益 ÷ 保有分の取得金額 × 100（取得金額0の場合は「—」）
- 今月の損益（回収済みを含む）= 現在の評価額 ＋ 今月の回収額 − 今月の投資額 − 月初繰越評価額

月をまたぐと投資額・回収額は当月分だけの集計に切り替わります。繰越保有分を新しい投資として計上せず、月初繰越評価額を差し引いて今月の損益を計算します。前月末の口数または基準価額が確認できない場合、今月の損益は「—」と表示します。保有分の取得金額・評価損益は継続して計算し、売買・口数補正の履歴も保存したままです。

金額は内部では端数を保持し、表示時に円単位に四捨五入します。口数と損益は概算で、税金・売却手数料等を含まず、実現損益や約定見込額ではありません。保有分を超える回収は、口数を計算できる時点で検出します。口数補正は投資額・回収額を変えず、評価額を通して損益に反映します。

選択した約定日の基準価額が未公表の場合、投資・回収の金額は集計し、口数・評価額・損益は **基準価額待ち** として「—」にします。公表後の再読込で計算を再開します。後の時点の実際の口数を補正した場合は、その口数と最新の公表済み基準価額で評価額を表示でき、月初繰越評価額も確認できれば今月の損益も表示します。回収分の取得金額が未確定の場合、平均取得単価・保有分の評価損益は公表まで「—」になります。別の日の基準価額で約定口数を計算することはありません。休業日や誤った日付を選んだ場合は履歴を取り消して登録し直してください。価格データが取得できない場合も損益を「—」と表示します。保存済み価格で表示する場合は、その旨と評価基準日を確認できます。保存に失敗した場合は画面に通知します。

## 評価損益0％の日経平均の目安

`（現在の平均取得単価 ÷ 当日より前の最新公表基準価額 − 1）× 100 ÷ 4.3` で計算します。含み損率をそのまま4.3で割る計算ではありません。たとえば平均取得単価50,000円、基準価額45,000円なら、基準価額の必要上昇率は約11.11％、日経平均の目安は約＋2.58％です。

保有分の取得金額を回収するためのラインで、月間損益や回収済みの金額は対象に含めません。基準価額の基準日・金額と損益0％になる基準価額も表示します。当日公表分があっても起点には使いません。負の騰落率は、基準日時点の含み益から損益0％までの下落余地を示します。0口、口数・取得単価が未確定、起点となる基準価額がない場合は「—」と表示します。

[運用会社の説明](https://www.rakuten-toushin.co.jp/fund/nav/ribla43/)にある日次約4.3倍という運用目標をもとに、日経平均で代用した単純な1日分のシナリオです。日経225先物と現物指数の差や費用等で実際の基準価額はずれるため、この騰落率での損益0％を保証するものではありません。日中の現在値からの追加上昇率や、複数日にまたがる指数騰落率は計算しません。

## ローカルで起動

Python 3.11以上を使用します。追加パッケージのインストールは不要です。このフォルダで実行してください。

```powershell
# 同梱の公表データを最新の公式CSVに更新（インターネット接続が必要）
python scripts/update_nav.py

# 公開用ファイルを生成し、ローカルサーバーを起動
python scripts/build_site.py
python -m http.server 4173 --bind 127.0.0.1
```

ブラウザで <http://127.0.0.1:4173/.site/> を開きます。終了はターミナルで `Ctrl+C`。修正を確認するときはビルドを再実行してページを再読込してください。`file://` 直開きは利用できません。

ビルドでは画面資産の内容からService Workerのリリース番号を生成します。価格だけの更新では画面キャッシュを作り直しません。`.site/` は生成物で、ソースに含まれる説明文書・テスト・スクリプトは公開されません。

## GitHub Pagesに公開

公開先は [hina-ce/nikkeibullbear](https://github.com/hina-ce/nikkeibullbear) です。公開用設定は以下のとおりです。

1. このフォルダの内容をデフォルトブランチ `main` に登録します。隠しフォルダ `.github/` と、実データの `data/nav.json` も含めてください。
2. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
3. **Settings → Actions → General** でワークフローが利用可能なことを確認します。組織側でトークンの書き込み権限が制限されている場合、データ更新のコミットができる設定も必要です。
4. **Actions → Update NAV and publish → Run workflow** を選び、`main` で実行します。
5. 成功した実行の **Deploy GitHub Pages** または **Settings → Pages** に公開URLが表示されます。通常は `https://ユーザー名.github.io/リポジトリ名/` です。

GitHub Freeでは公開リポジトリを使用します。アプリと価格データはURLを知っている人が閲覧できます。入力した保有情報は端末のブラウザ内だけに保存され、公開ファイルには含まれません。公開用の認証情報やシークレットの登録は不要です。

## 価格の自動更新と手動更新

`.github/workflows/publish.yml` が以下の時刻に公式CSVを取得します。

| 実行 | 日本時間 |
| --- | --- |
| 定期取得 | 月〜金 18:15〜23:45、30分間隔 |
| 翌朝の再取得 | 火〜土 6:15 |
| コードの更新 | `main` へのpush時 |
| 手動取得 | Actionsの **Run workflow** 実行時 |

各実行で投信の基準価額を取得します。祝日も取得を試みますが、履歴が同じならコミットや定期実行からの再公開は行いません。更新があったときだけJSONをコミットし、同じ実行内で公開します。手動実行とコードのpushでは、値が同じでも公開処理を実行します。ボットのコミットが再度ワークフローを起動することはありません。

取得失敗、形式変更、不正な日付・数値、保存済み履歴の欠落では処理を失敗させ、公開中のサイトを維持します。取得は最大3回試みます。データの訂正は、同じ日付の価格の変更として反映します。

GitHubの定期実行には遅延・実行漏れが発生する場合があります。また、公開リポジトリで60日間活動がないと定期実行が無効になる場合があります。通常は価格更新のコミットが継続しますが、長期間更新がないときは **Actions** で実行状態を確認し、必要に応じて有効化・手動実行してください。[GitHub公式の定期実行仕様](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

アプリの **再読込** は公開済みの基準価額JSONを読み直す操作です。掲載元への即時取得は、Actionsの **Run workflow** で行います。

## iPhoneに追加

1. HTTPSの公開URLをiPhoneのSafariで開きます。
2. Safariの共有メニューから **ホーム画面に追加** を選びます。表示される場合は **Webアプリとして開く** を有効にします。
3. 名前を確認して **追加**。ホーム画面の「4.3倍ブル」から起動できます。

一度オンラインで正常に読み込んだ画面とデータは、オフラインでも表示できます。通信失敗時は保存済みデータであることを明示します。Safariのサイトデータを削除した場合やOSが保存領域を解放した場合は、再びオンラインで開いてください。

## 更新できないとき

- 画面の基準日を確認してください。当日分が未公表の場合や休業日には日付が進みません。
- **Actions → Update NAV and publish** の最新実行を開き、赤いステップのログを確認します。
- **Fetch and save NAV** が失敗：配信元の通信状況やデータ形式を確認し、**Re-run jobs** で再試行します。不正なデータを手動で公開する必要はありません。
- `git push` が失敗：書き込み権限や `main` のブランチ保護を確認してください。ボットの直接pushが禁止されている場合は、この価格データ更新を許可できる運用設定が必要です。
- **Deploy GitHub Pages** が失敗：Pagesの公開元が **GitHub Actions** になっていることと、`github-pages` 環境が `main` からの公開を許可していることを確認します。
- 画面に保存失敗が表示される：端末の空き容量やSafariの保存制限を確認します。オンライン表示は継続できます。

Python標準ライブラリとNode.js 22以上の標準テストランナーだけを使用します。`npm install` は不要です。

```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
node --test
```

CSVの文字コード・列、無変更時の保存抑制、通信／データ／書き込み失敗時の既存値保持、週・年・日本時間の境界、金曜の代替日、前日比、画面の読み込み・初回失敗・保存値への復帰、サブディレクトリでのオフライン画面とキャッシュの分離を確認します。

保有情報については、1万口単位の損益計算、小数の平均取得単価、保有なし、旧形式からの引継ぎ、日付順の売買計算、月次入出金、日本時間の月替わり・年替わり、繰越残高を使う月間損益、全額回収後の損益、口数補正、基準価額待ちからの再計算、過大回収・不正入力の拒否、履歴の取消・復元、保存失敗時の表示を確認します。
